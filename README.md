# AI Document Assistant

A full-stack **RAG (Retrieval-Augmented Generation)** application that lets you chat with an AI or ask questions grounded in your own documents. Answers are generated by a large language model and cite the exact source text they came from.

**Live demo:** https://ragai-application.vercel.app/
---

## Features

- **Document Q&A (RAG):** Upload a document and ask questions answered only from its content, with the source passage shown for each answer.
- **General chat:** Talk to a general-purpose AI when no document is attached.
- **Semantic search:** Retrieval uses vector embeddings and cosine similarity, so questions match by *meaning*, not just keywords.
- **Multi-format ingestion:** Supports PDF, DOCX, and TXT files.
- **Real-time handling:** Politely declines real-time questions (date, time, weather) instead of hallucinating answers.
- **Responsive UI:** Custom developer-themed interface with a light/dark toggle that works on mobile and desktop.

---

## How the RAG pipeline works

1. **On upload** — the document text is extracted, split into chunks, and each chunk is converted into a vector embedding using Google Gemini (`gemini-embedding-001`). The chunks and their vectors are stored.
2. **On question** — the question is embedded the same way, compared against every chunk vector using **cosine similarity**, and the most relevant chunks are sent to the LLM as context.
3. **Answer** — the model generates a response grounded strictly in the retrieved chunks, and the UI displays the source passage.

This is what makes it a true RAG system rather than simple keyword search.

## Tech stack

**Frontend:** Angular 17 (standalone components, signals, routing), TypeScript, responsive CSS
**Backend:** FastAPI, Python
**AI:** Google Gemini API (chat + embeddings), vector embeddings, cosine-similarity retrieval
**Document parsing:** pypdf, python-docx
**Deployment:** Vercel (frontend), Render (backend)
**Other:** REST APIs, CORS, environment-based configuration, Git/GitHub

## Running locally

### Backend

```bash
cd backend
pip install -r requirements.txt
```

Create a `.env` file inside `backend/` with your Gemini API key:

```
GEMINI_API_KEY=your_key_here
GEMINI_MODEL=gemini-flash-latest
```

Then run:

```bash
python run.py
```

The API runs at `http://127.0.0.1:8000`.

### Frontend

```bash
cd frontend
npm install
npm start
```

The app runs at `http://localhost:4200`.

> Make sure `frontend/src/environments/environment.ts` points `apiBaseUrl` at your backend URL.

## Notes and limitations

- **PDF extraction quality varies with layout.** Text-based and single-column PDFs work well; layout-heavy or scanned PDFs extract less cleanly and would benefit from OCR — a known next step.
- **Free-tier hosting:** the backend sleeps when idle, so the first request after inactivity may take up to ~50 seconds to wake.
- **Embeddings and chat use Gemini free-tier quota**, which has daily limits.
